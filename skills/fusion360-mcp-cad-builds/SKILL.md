# Building CAD in Fusion 360 via the MCP server

## When
Creating/modifying parametric geometry in Fusion 360 through the fusion360-mcp-server tools — multi-feature parts, keyboard plates, enclosures, voronoi/lattice/topology-optimised cases. Use `fusion360_execute_code` for anything beyond 2-3 features; individual tool calls don't scale.

## Procedure
1. **Probe before building.** This Fusion build differs from docs: `component.bRepBodies` (NOT `.bodies`), features expose no `.bodies`, `Line3D` has no `.direction` (compute from start/end points), `BRepBody` has no `deleteObject()`. First call: `json.dumps({'attrs': [a for a in dir(design.rootComponent)...]})` to confirm the surface.
1a. **2026 API geometry names (verified 2026-09):** cylinder class is `adsk.core.Cylinder` (NOT `Cylinder3D`); `Cylinder` has `.origin` (axis point) + `.axis` (Vector3D) but NO `.center`; `adsk.core.Circle` does NOT exist — circular edges surface as `EllipticalArc3D` with `.center/.majorRadius/.minorRadius` (equal radii = circle); `BoundingBox3D` has NO `.center` — average min/max yourself; `Vector3D` has NO `dot`. Hole inventory pattern: walk `body.faces`, filter `g.objectType == adsk.core.Cylinder.classType()`, key by `round(g.radius*10,2)` with `g.origin*10` positions. Body deletion: `root.features.removeFeatures.add(body)` directly (NO createInput).
1b. **Sketch surgery is IMPOSSIBLE in this API**: `SketchPoint.geometry` and `SketchLine.geometry` are read-only, and `Sketch` has no `moveObjects`. To move/resize an existing cut region, build corrective bodies instead: a flat fill-patch (extrude the old region, NewBody) JOINed back, and/or a flat cutter (extrude the new region, taller than the part) combine-CUT — for tilted parts, tilt-move both with the same seating matrix before the boolean. Volume-checks catch mistakes (ΔV must equal the patch/cutter plan-area × thickness exactly).
2. **execute_code is REPL-style**: statements exec'd, last top-level statement eval'd and returned. End every script with a bare `RES` variable set in both the try and except — a trailing try/except block swallows the result AND your own defensive except hides the traceback. **Long scripts (~20KB+) can't be passed via a file path arg — the `code` param must be inline. Stage the script to a local file (written via bash/heredoc), then call execute_code with a one-liner `exec(open('/tmp/script.py').read()); RES` — keeps huge builds manageable and self-documenting.**
3. **Units are cm internally.** Define `MM = 0.1` and multiply every coordinate/distance (`V(v)` helper for ValueInput).
4. **"Part Design documents can only contain one component"** — 2026 Part-Design docs reject `occurrences.addNewComponent()` AND `constructionPlanes.setByPlane()` ("Environment is not supported"). Work with named BRepBodies in the root component; only native planes (XY + setByOffset) and the YZ/XZ construction planes work.
5. **JOIN merges into EVERY body it touches or pierces** — not just the one you're thinking of. Rules that prevent accidents:
   - Build the reference part completely first; build the overlapping part LAST as `NewBodyFeatureOperation`.
   - Scope every cut: `ei.participantBodies = [body]` — takes a **Python list**, NOT an ObjectCollection.
   - Ring/wall pieces that reach another body: extrude NewBody, then `combineFeatures` into the intended target only.
   - Separate bodies MAY overlap harmlessly; build a plate at its final XY inside the case, then moveFeatures it into place.
   - **Non-touching tool in a JOIN/CUT gets kept as a stray body named "<Target> (N)"** — after every combine, assert `len(root.bRepBodies) == expected` and delete strays with `removeFeatures.add(body)`. Select strays by GEOMETRY (smallest volume), never by name.
   - **Guaranteed-join patterns**: join order such that each added body volume-overlaps (not just touches) something already in the target — e.g. bosses standing in a solid rim band, wall-embedded posts piercing a ring.
   - **Clearance-pad rule**: whenever a bay/pocket is made by a clearance CUT then re-filled by a pad/lip body, make the pad EXACTLY BLANKET the clearance rect (pad edges = cut edges or beyond) — a 0.2–0.3mm overshoot of the cut past the pad leaves hairline through-slits in the floor that look like defects. Diagnose by scanning for thin planar faces at the cut plane's x/y with |normal| ≈ 1 and small area; FIX IN THE SCRIPT + rebuild (surgical fill patches compound into fins/face-soup — hit twice before learning).
   - **Heat-set insert posts (bottom-up assembly, proven)**: M2 insert (OD ~4) → **Ø7 boss** (~1.5mm plastic walls), Ø3.5×4.5 insert pocket blind-drilled from the post top (stop at plane−4.5), Ø2.4 screw through-bore below it, Ø4.2×2.5 head counterbore in the post foot at the case floor. Machine AFTER the wedge trim (plane height known; group cuts per post-row Y). Plate gets plain Ø2.4 clearance holes. Pair with slim Ø4.2 self-tap posts (Ø2.8×3.5 pilots) where lanes are too thin for Ø7. Post lanes around a PCB grid: with N×N tiles at pitch P and width P−0.05, ALL side lanes are ~(P−tile_width)/2… e.g. 19mm tiles on 19.05 leave only ~4mm side lanes — the lane beyond the last PCB row is the only fat one; place insert posts there and on the upper walls above the PCB zone.
6. **Angled cuts without angled planes** (Part Design): sketch the trapezoid on the native `yZConstructionPlane` and extrude as a **direct scoped CUT** (`setSymmetricExtent(V(20.0), True)`, `participants=[body]`) — preferred over the tool-body + combine-CUT dance, which intermittently throws "invalid input" after complex features (tapered cuts) appear in the timeline. **Native-plane mappings + extrude directions (all verified by probe bodies): XY normal +Z; yZ (u,v) → (y=v, z=−u), extrudes +X; xZ (u,v) → (x=u, z=−v), extrudes +Y.** Probe method when in doubt: tiny rect sketch → extrude NewBody 2mm → read bbox → `removeFeatures.add` (sketch transforms / Vector3D.dot are unusable in this API). A wedge at base b cuts everything above z = b + y·tanθ. A lip/collar band needs ONLY its TOP trim (base plane+lip_h) — never also apply a lower-base "bottom trim" wedge copied from ring-era code; a 9.5-base wedge removes-above-9.5-plane and eats the whole lip above y≈37.
7. **Repositioning bodies**: `root.features.moveFeatures.createInput(ObjectCollection([body]), matrix)` WORKS in Part Design. Build rotation matrices with `m.setWithCoordinateSystem(origin, xAxis, yAxis, zAxis)`. Seating transform for tilt θ about the front underside edge at height h: origin (0,0,h·MM), x=(1,0,0), y=(0,cosθ,sinθ), z=(0,−sinθ,cosθ) maps local (x,y,z) → (x, y·cosθ − z·sinθ, h + y·sinθ + z·cosθ). For rotation about arbitrary point c by matrix R (e.g. Rodrigues for tilting cut tools): use origin O = c − R·c with axes = R's columns. **Growing a case past its last feature row without moving internals**: extend the footprint to Y0 < 0 (or raise Y1) and keep the rim-plane equation in ASSEMBLY coords (z = h + y·tanθ) — the seating transform stays valid because plane(local_y·cosθ) = h + local_y·sinθ; parametrize Y0/Y1 through cut rects/boundary checks, pocket, corner slivers, ring, collar, wedge trapezoid span, and any seed-lattice range.
8. **Extrude pattern** (works, verified):
   ```python
   def ext(coll, dist_mm, op, start_mm=None, participants=None, sym_cm=None, taper_deg=None):
       ei = root.features.extrudeFeatures.createInput(coll, op)
       if start_mm is not None:
           ei.startExtent = adsk.fusion.OffsetStartDefinition.create(V(start_mm))
       if sym_cm is not None:
           ei.setSymmetricExtent(V(sym_cm), True)
       else:
           ei.setDistanceExtent(False, V(dist_mm))  # negative = -Z direction
       if taper_deg is not None:
           ei.taperAngle = V(math.radians(taper_deg))   # WORKS on cuts — walls lean
       if participants is not None:
           ei.participantBodies = list(participants)
       return root.features.extrudeFeatures.add(ei)
   ```
   Profiles: `sk.profiles.item(i)` by index; pick by area via `p.areaProperties().area` (cm²). Multi-profile NewBody extrude → collect created bodies by name-diffing `root.bRepBodies` before/after. Two nested rectangles give TWO profiles (inner + annulus), not three — pick annulus profiles by an area RANGE matching the actual band width (a 2.5mm wall band on an 85×108 case is ~9cm², not 20+).
8a. **Corner rounds without FilletFeature**: sketch a "sliver" profile per corner — two lines along the square corner plus one `sketchArcs.addByCenterStartSweep(center, startPt, sweep)` (±π/2); cut it through. Assertable by profile count. Parametrized corner function: the 4th-corner (x1,y1) arc START POINT is (x1−r, y1) — NOT (x1, y1), or the loop breaks.
8b. **Intersecting curves (slot merging into a bore, tangent circles, two rects sharing a corner region) must live in SEPARATE sketches/features** — intersecting sketch curves scramble profile topology; the cuts union in geometry. (Even two *filler* rects that overlap at a corner break the profile count assert.)
8c. **Spline-fitted organic cut loops**: for smooth curvy boundaries from polygon contours — decimate the polygon to ~60–85 points, `sk.sketchCurves.sketchFittedSplines.add(ObjectCollection_of_Points)`, close with a line from last to first point; the loop forms a normal profile. Works for TO/voronoi void outlines; decimation keeps pad-clearance margins (~±0.3mm wiggle vs ~0.7mm margins).
9. **Verify geometry programmatically**: cylinder-face histogram by radius (hole count/size), bbox per body (×10 for mm), volume vs hand-calc with hard ranges. **The #1 hand-calc trap (hit 3×): subtracted holes remove area × THICKNESS. Trap #2: ADDED bodies that embed in existing solid contribute only their NON-overlapping volume. Trap #3: histogram FACE counts are topology, not part counts — collars/rings fusing over post walls SPLIT faces; assert with ≥ / position checks, not ==.** When an assert fires on a plausible build, recompute the expectation before touching geometry. Position audits: every hole must sit in solid material; for tilted assemblies compensate mating features (boss XY = hole local XY under the plate transform). For sliver audits: scan planar faces with |n.x|≈1 or |n.y|≈1 lying at the known cut-plane coordinate, small area, low z-span → none should remain.
10. **Recovery is cheap**: `delete_all` + full deterministic rebuild script (fixed `random.Random(seed)` for pattern work) rather than surgical timeline edits — ESPECIALLY for thin/sliver artifacts, where patch features compound (fill-patches overshoot into fins, face-soup at 65.35/65.38/65.4/65.6/65.7 within two patches). Fix the script, rebuild, archive the script next to the exports. Scripts should assert loudly at each stage so failures leave a readable log. **When a governing dimension changes, sweep the script for hardcoded literals that DERIVE from it** — shell/prism heights must exceed the wedge plane at the new max extent; wedge spans, protection-zone offsets, sketch extents all scale; a bbox assert (zmax == base + L·tanθ) catches truncation. **Multiple trims: run the MAIN rim wedge before joining any lip band.** Fit-test coupons (flat slices exported as own STL then `removeFeatures`'d) let hardware iteration happen without reprinting the whole part — coupon at an X-offset outside the model, generator kept standalone.
11. **Export matrix** (this build):
   - `createSTEPExportOptions(path)` (whole design) → works; with a body arg → broken.
   - `createSTLExportOptions(body, path)` → works (body is arg 1!).
   - `createFusionArchiveExportOptions(path)` → works; snapshot BEFORE destructive rebuilds.
   - Saving is the user's job (Cmd+S).
11a. **Viewport renders** (for vision-model verification): `vp = app.activeViewport; c = vp.camera; c.eye/target/upVector = ...; vp.camera = c; vp.fit(); vp.saveAsImageFile(path, 1200, 900)`. **`vp.camera` returns a singleton — `viewOrientation` never overrides stale eye/target.** Always set eye/target/upVector explicitly (far ≈ 500+mm for quasi-orthographic elevations); verify render CONTENT with a vision delegation — mis-framed renders produce confident false verdicts. Low-angle underside shots (eye below the part) show lattice/sweep geometry best.
12. **Reverse-engineering reference geometry**: STEP is ASCII — regex `CARTESIAN_POINT`. Binary STL: `b''.join(data[84+50*i+12 : 84+50*i+48] ...)` then `struct.iter_unpack('<9f', ...)`.
13. **MCP plumbing on pi**: pi-mcp-adapter enumerates servers at session start — config edits need a reload. The fusion360 add-in has `runOnStartup: false`: if `execute_code` says "Not connected", check `nc -z localhost 9876`; user runs it from Fusion's ADD-INS dialog. Add-in log at `~/fusion360mcp.log`. Fusion itself may be closed between sessions — check the process, not just the port.
14. **Voronoi/lattice patterns (pure Python, no scipy)**:
   - Cells by half-plane clipping (Sutherland–Hodgman vs perpendicular bisectors). O(n²), fine ≤150 seeds. Cells are convex.
   - **Three seed flavours** (swap the seed-generation block only): (a) random + shallow wall-ownership ring + staggered inner ring; (b) hex = jittered triangular lattice (rows s·√3/2, alt rows +s/2, jitter ±0.14s → ~75% hexagons); (c) stress-graded look (Gaussian stress on loads + wall term; variable min-dist dart with symmetric radius acceptance; per-cell web inset by stress). All verified.
   - Web inset web/2 per edge EXCEPT boundary edges (d=0) — else wall holes are blind pockets.
   - **Vertical prisms make only RECTANGULAR wall openings.** Two organic-wall recipes: (i) tilt trick — extrude cells as bodies, rotate each ±8–17° about a random horizontal axis through its centroid (Rodrigues, item 7), combine-CUT all (~1 stray per 40-60 tools); (ii) WALL WINDOWS (simpler, better for solid-wall cases) — sketch on the wall's native plane (xZ for front/back: u=x, v=−z; yZ for sides: u=−z, v=y), draw top and bottom edges as two OPEN fitted splines riding sum-of-sines waves (24 pts, rng-seeded) + vertical closing lines at the ends, cut with offset-start extents per wall side (scoped). Keep-outs: post bores that pierce walls, USB/side slots, corners; keep a ≥2.5mm solid wall foot for desk bearing. NOTE: users may HATE wall windows on a clean case — they were reverted as "awful"; ask before applying.
   - Fake seeds (uncut cells) protect zones; exclude real seeds there too.
   - Seat preservation: flat cut ceiling (≈ plane−5 min) OR full cut + wedge-trimmed ring band re-added; lip/collar = extra band at plane+lip_h, extruded TALL past the highest trim, top-trimmed only, joined AFTER the main rim wedge.
   - Verify via standard-view renders + vision delegations ("irregular polygons, slanted edges, varied sizes, thin struts" catches skin pockets / rectangles / sparsity).
15. **REAL topology optimisation (SIMP) → CAD pipeline**:
   - **Architecture**: Fusion's embedded Python has NO numpy — solve in SYSTEM python via bash (numpy/scipy/skimage), write geometry as JSON to /tmp, `json.load()` inside `execute_code`. Heavy math local, geometry in Fusion.
   - **Solver** (2D SIMP, density filter, OC bisection, ~135 iters, 56×76 grid ≈ 8.8k DOF sparse ≈ 2min): non-design SOLID for wall band + post pads (locked at 1.0 — guarantees pads, untouched slots); volfrac 0.32, penal 3, rmin≈5mm, move 0.1. **NEVER hand-transcribe the 99-line KE — node-order mismatches make it non-SPD and the solver diverges with NEGATIVE compliance; Gauss-integrate the bilinear-quad KE (3 rigid-body zero eigenmodes = correct).** Vectorise assembly (EDOF map + np.tile(KE)) and energies via einsum.
   - **Extraction**: threshold RAW converged field at 0.5 → binary_closing×2 + binary_opening×1 → `skimage.measure.find_contours` (hand-rolled marching squares mis-pairs saddles) → drop border/tiny loops → Laplacian-smooth POLYGON vertices. **Do NOT blur the field pre-threshold (smears thin struts) or min-max-renormalize/quantile-pick thresholds (meaningless on near-binary fields).** Sanity: contour solid fraction must match mask fraction ±0.02.
   - **Result shape**: sparse-truss complement = typically ONE simply-connected void polygon (no islands = printable); cut as a single loop, flat ceiling below the seat band; walls solid → no ring-restore needed. Archive solver + JSON next to exports; knobs volfrac/rmin.
   - **"Sweepy" generative finish (proven)**: density-field TIERING is usually dead — converged fields are ~88% saturated (check the histogram FIRST; grey bands ≤2%); even the filtered field is ≥0.55 inside solid. Get the look three ways instead: (1) spline-fit the void contour (item 8c); (2) taper the void cut 4° via `taperAngle` (struts thicker at base); (3) INSET TOP-STEP — erode the solid mask ~3mm, contour + spline that, cut z (ceiling−2.4)..(ceiling+0.1) → flowing stepped band along every strut edge. Renders from low underside angles sell it.
